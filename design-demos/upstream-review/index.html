SkillManager 软链接扫描src/main/skills/SkillManager.ts
推荐同步

支持公共 Skill 目录复用，并用 realpath 阻断软链接递归环。

  • 改动集中，和 Neo UI 定制几乎没有交集。
  • 需要同步对应测试，确认 Windows 符号链接权限场景。
  • 属于“加固扫描边界”，不改变已有 Skill 管理 API。
Windows NUL 重定向保护resources/extensions/pi-deck-nul-redirect-fix.ts
推荐同步

避免 Agent 执行 > nul 时生成 Windows 设备名垃圾文件。

  • 只监听 Pi 内置 bash 工具，不影响用户手动命令。
  • 需要加入 ExtensionManager 的内置扩展部署清单。
  • 纯 Windows 行为，Linux/macOS 直接透传。
WSL / Pi 启动修复PiLocator · PiProcess · AgentManager
按需研究

修复 WSL 路径解析和 Agent 启动等待，但会触及我们已有会话归属逻辑。

  • 如果不使用 WSL，收益有限。
  • 需要围绕 session cwd 做定向移植，不能整包覆盖。
  • 建议先用真实 WSL 场景复现，再决定是否动。
Git 面板与消息队列GitPanel · queuedPromptQueue · 大量 App.tsx 改动
暂缓

能力很完整，但依赖面太大，容易覆盖 Neo 启动页、聊天和布局定制。

  • Git 面板不是单文件功能，需要整组 IPC 与状态链路。
  • 队列逻辑可以以后抽出纯函数单独移植。
  • 现在同步的冲突成本高于立即收益。
当前结论先移植 2 个低风险修复；WSL 和大功能保持观察，不覆盖本地 Neo 提交。
