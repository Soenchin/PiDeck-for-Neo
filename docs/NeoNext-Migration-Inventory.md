# NeoNext 搬家清单：当前 NeoNisch 定制盘点

> **用途**：从旧版 PiDeck for NeoNisch 搬往基于上游 `v0.7.1` 的 NeoNext 时，作为产品需求、资产清单与验收边界。
>
> **盘点日期**：2026-08-20  
> **旧屋基线**：本仓库 `main`，版本 `0.6.5`  
> **新屋地基**：上游 `ayuayue/PiDeck` 的正式 tag `v0.7.1`（commit `1979f98d`），**不使用**仅改版本号的 `0.7.2-beta` main。  
> **迁移原则**：不 merge 旧 `main`；以新版的 Session-first 架构为底座，按此清单重新实现/适配 NeoNisch 能力。

---

## 0. 搬家时的三条硬边界

1. **旧屋不能拆。** 当前 `main` 是可用稳定版本；NeoNext 必须在独立分支/独立 worktree 中开发。不要 rebase、覆盖或强推现有 `neo/main`。
2. **不复制记忆库。** Neo 的权威长期记忆仍只有 `X:\CC\memory\` 和 Houkai；新应用连接原有 Pi Agent 配置与扩展，不建立 PiDeck 私有的第三份记忆库。
3. **先保留协作语义，再补装饰。** Logo 能晚一小时，`ask_question` 取消语义、会话归属、ROCKET 隔离和远程访问安全不能丢一次。

### 2.2 应用视觉语言（必须遵守）

- **基调**：深黑绿、安静、克制、开发工具感；不是通用 PiDeck，也不是高饱和赛博面板。
- **视觉重心**：绿色主要落在 Logo、状态和少量关键动作；字标应是浅灰绿，不跟 Logo 抢戏。
- **空间结构**：桌面仍以「左侧项目/Agent、中央对话、右侧上下文/工作台、底部终端」为主。新版的 Session Tab / 分屏可以加入，但不要把核心体验改成营销页或卡片墙。
- **交互气质**：高频控制靠近工作区、状态明确、不过度弹窗；跨会话的小问题用稳定状态提示而非声音/闪烁骚扰。
- **字体职责**：品牌短标题用 Montserrat；技术路径/模型 ID/端口用等宽字体；中文正文优先系统 UI 字体。
- **国际化**：用户可见中英文必须进入 i18n；中文是默认工作语言，但不能以硬编码中文替代翻译键。

### 2.3 两套“视觉偏好”不能混淆

| 领域 | 应该如何使用 | 不该如何使用 |
|---|---|---|
| PiDeck 应用 UI | 深黑绿、低噪声、紧凑但不压迫的协作工作台 | 不把每个控件做成霓虹灯、玻璃球或概念海报 |
| Neo 创作/生图默认审美 | 近黑石墨、旧石灰混凝土、低饱和靛蓝/煤蓝、少量脏金/旧铜；悬浮粗野派、巨构、明确色块、克制留白 | 不默认套青橙电影色、赛博霓虹、哥特尖塔、杂乱垃圾废土；也不强行移植到应用 UI |

> 创作偏好服从当次提示、参考图和局部重绘边界；它是 Neo 的内容创作母题，不是桌面应用的主题包。

## 3. P0：新屋第一天就要能保住的协作语义

### 3.1 会话和 Agent 的正确性

| 能力 | 当前行为 / 规则 | 迁移注意 |
|---|---|---|
| 会话归属 | **只按 session 文件自身的 `cwd` / `projectPath`** 归属；绝不从消息文本里的路径猜测项目 | 新版 Session-first 已更接近正确模型，但必须回归测试嵌套项目，不能重现 session hijack |
| Agent 复用 | 同一 `sessionPath` 全局复用同一 Agent，避免重复运行与状态分裂 | 新版 runtime 本来按 session 管理，需验证同路径多入口仍是一个运行体 |
| 压缩可靠性 | 使用 Pi 的 `customInstructions`；RPC 超时至少继承设置；所有成功/失败/取消/重连路径 `finally` 收口 loading；后台刷新历史不阻塞 UI | 不可因新版 compaction UI 漂亮就丢掉这些生命周期边界；需用现有 `compactionLifecycle` 语义回归 |
| 压缩后历史 | 压缩后仍可保留完整历史供阅读与恢复 | 新版分页机制是收益点，但必须验证压缩前后消息不丢、不串轮 |
| 自动中文标题 | 首轮回答结束或压缩结束后后台生成 ≤15 字中文标题；走独立 Pi 进程、不污染原会话；用户手动改名后永久锁定 | 新版会话标题/Tab 必须尊重手动锁；重启后标题不能丢 |
| 会话置顶 | 按 `pinnedAt` 排序，置顶会话不被普通列表截断 | 新版有自己的 Tab pin，不能误把“Session Tab 固定”当成“侧栏会话置顶”；两者用途不同 |
| 小问题提醒 | 某个后台会话等待主人回答时，跨会话显示稳定状态，提醒但不打扰 | 对接新版 ask 面板与 session 状态；不依赖 transient toast |
| 未读完成点 | 后台 Agent 完成后在侧栏显示绿色未读点 | 必须与新版 session runtime 状态对齐 |

### 3.2 `ask_question` 是核心交互，不是普通工具卡

当前扩展位于 `resources/extensions/pi-deck-ask-question.ts`。它是 Neo 工作方式的一部分，迁移验收应逐项覆盖：

- 所有需要用户选择、确认、短文本或长文本输入的情形，都必须走 `ask_question`，不能把问题塞进普通回复里等主人猜。
- 支持单题与批量题；`select` 支持可选的自定义输入；`confirm` / `input` / `editor` 语义完整。
- **取消必须真的是取消**：Stop / `null` 结果不会悄悄选择第一项，也不会留下卡死的 pending UI。
- 待回答问题显示在 Composer 上方的内联卡片，不再强制全屏 modal；历史里仍保留工具结果。
- pending 请求按 session / Agent 隔离；Composer 禁用与草稿保留必须正确；多会话来回切换不串题。
- 桌面与手机端都能回答；手机侧通过 `/api/agents/:id/ui-response` 回传，SSE/状态补偿后仍能重现 pending 问题。

### 3.3 高频协作体验

| 能力 | 当前规则 | 新版落点 |
|---|---|---|
| 文件引用 | Composer 可把文件/路径插成引用 token，带空格路径不能被截断 | 对接新版 TipTap Composer / 引用 chip，而不是恢复旧输入框 |
| 任务产物预览 | 从成功 `write/edit/create/patch` 识别真实修改文件；图片/SVG/HTML 就地预览，普通文件交给系统；最多 3 个；HTML sandbox，IPC 有项目/Agent/临时目录校验 | 新版每回合文件变更与 split viewer 可复用；本地“任务产物卡”安全边界需单独接回 |
| Git 工作区 | Files 抽屉有 working tree / commits / remote 视图、提交时间、紧凑布局 | 新版 Git 行内操作与大 diff 更强。先对照能力，保留我们需要的工作树/历史/远端信息，不搬旧 UI 壳 |
| 缓存诊断 | 显示累计会话 cache-hit，帮助看模型缓存是否真的命中 | 新版已有统计体系；要确认口径可解释且按当前会话可见 |
| 更新策略 | 彻底关闭启动/后台自动更新检查，只保留设置里的手动检查 | 这是工作流偏好，不能被上游默认行为反向打开 |
| 代理/连接诊断 | 区分 pi Agent 子进程代理与桌面模型请求代理，便于排故 | 对照新版设置与日志，不丢诊断路径 |

## 4. P1：Neo 专属能力与远程访问

### 4.1 Neo × ROCKET 双 Agent 房间

**这不是多开两个普通聊天 Tab。** 当前由 `RoomManager` 在桌面协作层编排，不改 Pi 核心。

- 入口常驻侧栏搜索框下、普通聊天/项目列表上；进入后显示独立房间时间线。
- 支持 `@Neo`、`@ROCKET`、`@两人` 路由，图片粘贴、停止当前回答、分别选模型、点击“让另一位接话”。
- 禁止两位 Agent 无限互相自动触发。
- 两人各自一个 `pi --mode rpc` 进程、独立 Session；房间配置/路径/历史跨重启恢复；“清屏”只清画面，“新开一桌”才各自新建上下文。
- **身份与记忆隔离是 P0 级安全约束**：
  - Neo 使用真实全局 Neo 人格，记忆为 `X:\CC\memory\` + Houkai。
  - ROCKET 使用 `X:\CC\projects\ROCKET\CLAUDE.md` 与自己的 `X:\CC\projects\ROCKET\memory\`；独立 `PI_CODING_AGENT_DIR`，不加载 Neo 的 `APPEND_SYSTEM.md`，使用 `--no-extensions`；禁止访问 Houkai、`memory_search`、`memory_commit`。
- 新版 Session-first 的 Agent/session 绑定会改变 RoomManager 接入方式；迁移时应把 Room 当成“外层编排器”，而非往核心 session reducer 里塞特例。

### 4.2 Mobile Remote：安全规则先于 UI

**产品定位**：手机只是控制电脑上的 PiDeck / 本地 Agent；手机端是独立的“项目 → 会话 → 聊天”界面，不是把桌面三栏硬压到 390px。

已实现并应保留的协议/安全规则：

- LAN Web 服务开启后生成随机 token；除 health 外所有 `/api/*` 都要求 `Authorization: Bearer <token>`，比较使用 timing-safe；前端 URL token 仅消费后存本地。
- same-origin only，不开宽松 CORS；请求 body 上限 2MB；按 IP 限流，连续鉴权失败锁定。
- 会话 ID 使用 `SHA-256(sessionPath)` 的 opaque ID，手机不看到真实本机路径；服务端严格解析、拒绝 `..` 与非法 session path。
- 命令走 REST；状态、流式回复与 ask UI 走 SSE。断线、正常 EOF、手机回前台/网络恢复都重连；连接后补当前 state 与消息快照；背压只保留最新快照，不能回放旧事件风暴。
- `ask_question` 的 UI 请求和回应在手机上与桌面等价。
- PWA manifest / 图标已准备，但纯 HTTP 局域网不能可靠安装成 Android PWA；当前沉浸容器方案是 Hermit。以后外网可走 HTTPS 隧道，不把本机端口裸暴露。

当前移动 UI 状态：基础单栏、汉堡侧栏/遮罩、移动端 Neo Logo、状态详情底部弹板已做；**尚未完成**触屏密度、聊天顶栏 Logo、移动设置精简。搬新家后更建议按新版 Web UI / API 单独重做，而不是复制旧 `mobile.css`。

### 4.3 外网连接不是仓库代码

外网入口、Cloudflare Tunnel 进程、token、网络规则和设备配对属于机器运维配置：

- 新版本先在 localhost / LAN 验证，再手工接回已有 Tunnel。
- 不把 token、Tunnel 凭证、证书、真实局域网 IP 或代理规则提交到仓库、截图或文档。
- 迁移验收包含断线重连、手机前后台切换、旧 session 打开和 ask 回答；不只验证“首页能开”。

## 5. P2：当前已在用的自动化与用量能力

这些能力不应从需求清单里消失，但可让旧屋继续跑，等 P0/P1 稳后再迁。

### 5.1 Provider 用量和状态

- **DDD**：用量、缓存统计、订阅日额度剩余；订阅余额与钱包余额不能混为一个数。
- **SX**：独立 SX 用量服务与状态面板适配。
- **DeepSeek**：独立余额/用量接入；按真实 provider / hostname 判断归属，不能只看模型名里是否含 `DeepSeek`。
- UI 显示时保留币种与缓存含义，避免把“剩余额度”“余额”“实际扣费”混在一起。

### 5.2 每日总结（已实现）

- 这是 PiDeck 自动化页现有功能：定时整理当天对话，弹出可编辑审核，再确认保存到记忆系统。
- 对话时间戳兼容 ISO 字符串和数字毫秒，避免当天消息被误判为 0。
- 当前每日总结复用单个 Agent，并有固定模型策略。新实现不能为“自动化方便”绕过审核与双写规则。

### 5.3 空闲自主活动（已实现，边界很严）

- Windows 系统空闲满 **40 分钟**，且 PresenceProbe 判定为 `AWAY`，才启动独立自主 Agent。
- 可选择搜索/小游戏活动；模型可单独指定，未填则使用 Pi 默认模型。
- 同一次缺席中，续轮按上一轮 prompt 启动时刻算，最低间隔 **60 分钟**；单会话总时长上限 **90 分钟 / 12 轮**。
- 主人回来、关闭功能或退出时，待续轮定时器必须立刻取消；会话完成/报错后，主人回到电脑前不得自动重启。
- 这条节流与回归规则来自实际“秒级任务每分钟续轮”的事故，不能简化掉。

### 5.4 每日记忆回顾（尚未实现，不能误迁）

已定的是**极简未来方案**，不是当前代码：23:55（宽限至 00:05、每日锁）启动受限 Pi Agent；它自己扫描过去 24h 顶层用户会话、用 `memory_search` 去重、给出 5–8 条候选并逐条 `memory_commit` 确认。没有 byte offset 状态机、隐藏项目或专用 UI。

## 6. 使用习惯如何变成产品要求

这些不是“人设文案”，而是决定工作台交互取舍的真实约束。

| 观察到的习惯 | NeoNext 应对 |
|---|---|
| 主要在下午和晚上处理重活，深夜仍会续一会 | 不用每日自动更新/无意义弹窗打断；夜间自动化必须可审计、可取消 |
| 约四分之一是 `继续`、`看看`、`不对` 这类短弹幕指令 | Composer 需要随时可用、状态切换快；短消息不能被复杂流程吞掉 |
| 长内容通常是日志、报错、截图、文件路径现场 | 文件引用、粘贴图片、工具输出展开/按需读取、错误诊断优先级高于花哨卡片 |
| 会快速试、快速叫停，并认真比对修复是否真的对 | Stop/取消必须是确定语义；错误要给真实原因；不可用假成功/静默 fallback 糊弄 |
| 会追问原理和边界，不是只要结果 | 状态、用量、模型、缓存、会话归属应有可解释信息，而不是黑盒 |
| 需要跨会话长期协作 | 自动标题、完整历史、会话定位、未读/小问题提示和未来全文检索都很重要 |
| 设备重心是 Windows 桌面，手机是远程控制补充 | 桌面三栏效率优先；移动端只做高频控制，不照搬完整桌面工作台 |
| 默认中文协作，技术内容可中英混用 | i18n 的中文质量、路径/模型等原文可读性必须保住 |

### 工作方式的产品约束

- 主人是编程初学者：界面和报错要说清楚“为什么、下一步怎么做”，不是只抛内部术语。
- 构建、打包、覆盖运行产物、关闭或重启应用都需要主人明确批准；迁移开发期间亦然。

## 9. 搬家完成的最低验收场景

NeoNext 在替代旧屋前，至少应通过下列手工/自动化验收。没有这些，就只能算装修样板间。

1. **品牌启动**：深浅环境均显示 Logo A；启动无闪白、无卡死；桌面/移动标志一致。
2. **项目归属**：打开嵌套项目的旧 session，正确归到其自身 `cwd/projectPath`，不被父/子项目抢走；同 session 不重复开 Agent。
3. **历史与流式**：长流式消息稳定、上翻历史不被拽回底部；长工具输出按需加载；压缩前后完整历史可读且不重复/丢失。
4. **问答**：单题、批量 select、自定义输入、confirm、editor、取消、Stop、多会话切换均正确；桌面和手机都能回传答案。
5. **协作状态**：自动中文标题可生成且手动标题不被覆盖；置顶、小问题、后台完成未读状态保持。
6. **Neo × ROCKET**：两人模型独立、Session 独立、记忆权限隔离；不会无限自言自语；新开一桌不删除旧历史。
7. **远程安全**：无 token 不能进入 API；不泄露真实 session 路径；断线重连后消息与 pending ask 恢复；手机端不开放桌面端无关能力。
8. **安全工作流**：更新仍手动；构建/重启不被自动触发；凭据与记忆库没有进入仓库；审计/日志可定位问题但不记录密钥。
9. **自动化（P2 收口时）**：每日总结需审核；自主活动遵守 40 分钟空闲、60 分钟续轮、90 分钟/12 轮上限与主人返回即停。
